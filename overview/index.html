EPUB to Audiobook
any book, read aloud and highlighted

A free desktop app, English, Mandarin and Cantonese

Turn any EPUB into an audiobook and read along as it plays.

Point it at a .epub and it detects the chapters, flags front and back matter, and renders chapter-named MP3s (or one .m4b with chapter markers) with Microsoft's free edge-tts neural voices. The player then highlights each sentence as it is spoken, timed by the boundary events edge-tts emits with the audio. It needs no API key and costs nothing to run.

Step one

It finds the chapters and flags the junk

Before synthesizing anything, --list parses the book and prints what it found: chapters, front and back matter, word counts, an estimated runtime, and how many parts each chapter will be split into.

The [junk?] flags come from title and filename patterns plus a minimum length. Nothing is dropped silently; the GUI lets you untick flagged sections, and --skip-junk drops them on the command line.

Read-along

Timed by the speech engine

V2 split each chapter into sentences with its own splitter, then matched those sentences to edge-tts's boundary events by greedy text matching. The two rarely produced the same number of segments, so the highlight drifted further out of sync the longer a track ran.

86segments timed by edge-tts in one part
77sentences from the app's own splitter for the same part

Since V3 the player uses edge-tts's boundary events directly as the highlight units, so each highlighted span is exactly the span the engine timed. The sample at the top shows the mismatch on a small scale: edge-tts timed nine units for that passage, and the engine's own split_sentences() finds six. Units are made contiguous so the highlight never flickers between sentences, and each file's audio duration is stored for an exact seek bar. The timings live in a .subs.json sidecar next to each MP3.

Chinese needed its own handling: splitting on 。！？；, sizing parts by characters at about 300 a minute, and switching the reader to PingFang SC, HK or TC. edge-tts's own Chinese sentence timing keeps Mandarin and Cantonese in sync the same way.

Six versions

V6 is about finding ffmpeg

V1 was the pipeline (extraction, chapter detection, synthesis, atomic writes and resume), and V2 added the timing sidecars, tags and .m4b. V3 and V4 brought the interface and the drift fix; V5 added Chinese.

V6 is almost entirely ffmpeg discovery. It looks in the usual install locations (winget, Chocolatey, Scoop, Homebrew, /usr/bin, a bundled ffmpeg/ folder, or FFMPEG_DIR) as well as PATH, prints the exact install command for your OS when ffmpeg is missing, and will use an ffmpeg shipped next to the app. Speed control and .m4b export now work on a fresh machine.

Limitations

Desktop only, and you bring the books

It is a Python desktop app with a Tkinter interface. The read-along at the top of this page replays the engine's real output in the browser, but the app itself does not run there. Launchers are included for Windows and macOS, plus a script that builds a double-clickable macOS .app.

Synthesis needs an internet connection, because the voices are Microsoft's hosted edge-tts service. ffmpeg is optional and needed only for speed control and .m4b. The repository ships no books, and its only audio is the 73-second public-domain sample above; use books you own or public-domain titles, for personal listening.

There are no screenshots of the player on this page. A capture of the desktop window was blocked by a macOS screen-recording permission prompt and has not been retaken. The command-line listing and the read-along sample are the captured output shown here.
